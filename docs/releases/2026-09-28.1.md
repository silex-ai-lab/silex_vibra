# 2026-09-28.1 — Fix Codex session navigation warnings

Source-only release; no prebuilt app is attached. Build from source using the
[installation instructions](https://github.com/silex-ai-lab/silex_vibra/tree/2026-09-28.1#install).

## Fixed

Two Codex sessions could both report "That session has no terminal" because
their thread locks were held by the same managed background server. Vibra
treated that writer as the interactive terminal client.

- Recognize managed Codex servers and open each session's exact conversation
  through the Codex desktop app's thread link. This opens the desktop
  conversation; it does not focus the original CLI tab.
- When that desktop link cannot be opened, show history for the selected
  session without a blocking alert. Missing-process and missing-terminal
  navigation failures use the same nonmodal fallback.
- Filter fallback history by session ID, keeping same-project sessions
  separate. Select the newest available question and provide an All sessions
  button to return to general history.
- Failed navigation in History no longer changes the clipboard or incorrectly
  claims that the session has exited.
- Report shared-server ownership in `--locate`; allow `--jump` to take a
  session ID as well as a project name.

## Verification and remaining limits

- All 168 tests passed, including daemon recognition, thread-link validation,
  and exact-session history filtering. Release build passed.
- Live diagnostics identified both reported sessions as shared-server threads.
  The local app was installed using its existing signing identity.
- End-to-end desktop navigation was not visually verified: the UI tool exposed
  only Vibra's overlay and denied access to iTerm.
- A daemon-held lock does not prove that a user still has a session open.
  Faster exit detection, stale working-state cleanup, and exact mapping from
  shared-server threads to terminal clients remain future work. Terminal
  Automation permission errors and unmatched terminal ownership retain their
  existing handling.
