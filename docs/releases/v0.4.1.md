# v0.4.1 — Needs You first, code checks, and a review of agent activity

Source-only release; no prebuilt app is attached. Install or update with
Homebrew once the tap moves to 0.4.1 (`brew install silex-ai-lab/tap/vibra`, or
`brew upgrade silex-ai-lab/tap/vibra` from 0.3.0), or build from source with the
[installation instructions](https://github.com/silex-ai-lab/silex_vibra/tree/v0.4.1#install).

## New

- **A first-use loop.** The menu leads with **Needs You** across all agents. A
  Setup window shows what was found for each agent, the notification state and
  Launch at login. Agents that appear after launch are found without a relaunch.
- **Return to Session in Orca.** Clicking a Claude Code or Codex session running
  in an Orca terminal switches Orca to that terminal.
- **Code checks in Session Details** (Claude Code and Codex). Whether a test,
  build or lint command ran after the session's last code change, and what it
  returned. It reports only what the transcript shows, and never says a task is
  done.
- **Review Agent Activity** (Claude Code and Codex). Findings such as denied
  calls that ran later, credential reads, writes outside the workspace, force
  pushes, unrestricted sessions and authentication failures. You answer each
  one, or draft a report to the vendor and send it yourself. A usage file you
  fetch with your own key can be imported to flag days this Mac cannot explain.
  Some findings cover Claude Code only; see
  [features](https://github.com/silex-ai-lab/silex_vibra/blob/v0.4.1/docs/features.md#review-agent-activity).

## Fixed

- Vibra builds with Swift 6.1 (Xcode 16, macOS 15 Command Line Tools). The
  `v0.4.0` tag compiled only with newer Swift, so it was not released; 0.4.1 is
  the first release with the features below.
- A vendor usage file with usage on a day after today (UTC) is refused instead
  of being compared with this Mac's usage. An empty day after today is ignored.

## What Vibra now stores

Vibra makes no network request. This release adds the first file it persists
beyond preferences: `~/Library/Application Support/Vibra/incidents.json`, which
holds hashed incident ids, your answers and their dates, and one notification
timestamp. Removing the app does not remove it. To remove all saved data:

```sh
rm -rf ~/Library/Application\ Support/Vibra
defaults delete ai.silexlab.vibra
```

## Verification

- CI builds the app and runs all 502 tests on the macOS 15 runners with Swift
  6.1.2, on Apple Silicon and Intel.
- `make test`: 502 tests in 60 suites passed on macOS 27.0.1 with Swift 6.4,
  including the four canaries that plant fake secrets and message text and check
  none of it leaks into sessions, JSON, reports, evidence or incidents.
- The future-day refusal was test-first: its tests failed on the base with the
  predicted results (15 issues), then passed. The empty-padding rule and its
  precedence under the age limit are pinned the other way: with the padding
  guard removed, both of their tests fail.
- The installed 0.4.1 bundle's `--incidents --days 7` and `--query` exit 0.
- `tools/readme-anchors.sh` checks all four READMEs for the new features and the
  corrected removal text.

## Limits still open

- The app is ad-hoc signed, not Developer ID signed or notarized, so
  notifications need one manual step in System Settings, and notification
  delivery for incidents was not exercised.
- The vendor usage import was tested on the documented page shapes, not on a
  real downloaded file.
