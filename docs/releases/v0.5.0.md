# v0.5.0: wait statistics, test edits in Code checks, OWASP categories

Source-only release; no prebuilt app is attached. Install or update with
Homebrew once the tap moves to 0.5.0 (`brew install silex-ai-lab/tap/vibra`, or
`brew upgrade silex-ai-lab/tap/vibra`), or build from source with the
[installation instructions](https://github.com/silex-ai-lab/silex_vibra/tree/v0.5.0#install).

This is not a Developer ID signed or notarized build. The release scripts for
one are in the repository, but the certificate does not exist yet.

## Fixed

- **Clicking a session that runs as an Orca chat brings Orca forward.** Before,
  the click opened the History window. An Orca chat has no terminal and runs
  under Orca's daemon host, so Vibra found no host app and reported "process
  has no controlling terminal". Vibra now falls back to the running Orca when
  the session's process ancestry names Orca. Orca's CLI has no command to
  focus a chat tab, so the app comes forward and the tab is not selected.
- **Codex History no longer lists prompts its subagents received,** or
  injected heartbeat, notification and shell-command text, as questions you
  typed. A Codex session spawned for a subagent (the approval guardian, a
  spawned thread) now counts as unattended, as `codex exec` already did.

## Added

- **`Vibra --wait-stats` measures how long sessions waited on you.** For
  Claude Code and Codex, from local transcripts, it prints per agent: sessions,
  waits by kind (a finished turn until your next prompt or slash command; an
  `AskUserQuestion` until your answer; a tool call you approved or rejected
  until its result), quartiles of their length in seconds with each wait
  capped at 2 h, and blocked minutes per session with and without waits over
  the cap. `--days N` (default 30) or `--from YYYY-MM-DD --to YYYY-MM-DD` in
  local time. It prints counts and durations only: no id, path or text. It is
  a command-line report. There is no menu or window for it.
- **Code checks says when test-file edits changed its test-pattern counts.** When the reported check
  is a passing test run and the test run just before it failed, the row adds
  one sentence if edits to test files in between lowered Vibra's assertion or
  test-function matches, or raised its skip, focus (`.only`) or
  expected-failure matches. For example, "Between a failed test run that finished
  12m ago and this run, edits to test files changed Vibra's text-pattern counts
  in the edited text: fewer assertion matches. Vibra matches text patterns in
  the edited text only; it does not parse code or read the whole file." Only
  Claude Code `Edit` and `MultiEdit` edits are counted. A file with an edit
  that overlaps either end of the window, or that Vibra cannot count, is left
  out. See [Code checks](../features.md) for the rule and its known limits.
- **A related OWASP category on each Review Agent Activity finding.** Credential
  reads, this project's `.env` named and guardrails off relate to ASI03. A
  denied call that ran later, a write outside the workspace and a force push
  relate to ASI02. Vendor credential rejections and vendor usage relate to
  none. `--incidents --json` carries an `owasp` array on every row. A vendor
  report draft adds one "Related OWASP category (Top 10 for Agentic
  Applications 2026)" line after the facts. It is context, not a finding
  against the vendor.
- **`--evidence-stats`** change lines carry `target=source`, `test.compared` or
  `test.unseen`, and new `qualified agent= effect=` lines count rows whose
  test-edit sentence names an effect.

## Changed

- **Release build.** `make app ARCHS="arm64 x86_64" HARDENED=1` builds a
  universal app with the hardened runtime and the Apple Events entitlement.
  `make dmg` only packages an existing bundle and never rebuilds.
  `tools/release/package.sh` is the one script both CI and the release
  workflow run. A plain `make app` is unchanged, and it is what Homebrew and a
  source build use.

## What Vibra now stores

Nothing new. `--wait-stats` reads transcripts and prints counts and durations.
Test-edit text is read in memory to count pattern matches and dropped. A test
file's path becomes an in-memory hash key. Vibra still makes no network
request.

## Verification

- CI builds the app, runs all 622 tests and launches the app on the macOS 15
  runners with Swift 6.1.2, on Apple Silicon and Intel. On both, the package
  dry run checks the app inside the mounted DMG.
- `make test` requires the five privacy canaries to pass by name, including
  `waitSentinelsNeverLeak` for `--wait-stats`.
- An independent Python oracle (`tools/wait-oracle/`) agrees with
  `--wait-stats` byte for byte on nine shared fixture scenarios and on a
  frozen snapshot of the owner's month. The first n=1 pilot is in
  `docs/research/2026-11-12/wait-pilot.md`.
- An independent Python oracle (`tools/evidence-oracle`) implements the
  test-edit rule. On the owner's 30 days of sessions, its `--evidence-stats`
  counts matched the Swift build on every change, check and reported line, in
  both run orders. The only differences were sessions that started between the
  two runs. Neither found a qualifying row. So on that data the test-edit
  sentence appeared 0 times.
- The Orca chat fix was checked with `Vibra --jump <session>` on a live Orca
  chat session: before, "FAIL: process has no controlling terminal"; after,
  "OK: focused in Orca". No automated test covers it.

## Limits still open

- A click on an Orca chat session brings Orca forward but does not select the
  chat tab.
- The test-edit sentence has the known limits listed in `docs/features.md`. On
  the owner's own 30-day data it fired 0 times.
- The app is ad-hoc signed, not Developer ID signed or notarized, so
  notifications need one manual step in System Settings. The tag's release
  workflow cannot sign until the certificate and its secrets exist.
- There is no prebuilt Homebrew cask yet. The tap still builds from source.
