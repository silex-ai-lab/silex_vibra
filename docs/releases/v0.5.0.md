# v0.5.0: test edits in Code checks, OWASP categories, a signed DMG

> Draft. These notes describe the branch `feat/release-and-test-integrity`.
> They become final only when plan task 14 passes, meaning the tagged release
> is notarized, stapled and accepted by Gatekeeper. If task 14 fails, this is not
> a notarized build and the install section below does not apply.

If task 14 passes, this is Vibra's first Developer ID signed and notarized
build. Download `Vibra-0.5.0.dmg` from this release, check it against

(`brew install silex-ai-lab/tap/vibra`) and building from source keep working
as before.

## Added

- **Code checks says when test-file edits changed its test-pattern counts.** When the reported check
  is a passing test run and the test run just before it failed, the row adds
  one sentence if edits to test files in between lowered Vibra's assertion or
  test-function matches, or raised its skip, focus (`.only`) or
  expected-failure matches. For example, "Between a failed test run that finished
  12m ago and this run, edits to test files changed Vibra's text-pattern counts
  in the edited text: fewer assertion matches. Vibra matches text patterns in
  the edited text only; it does not parse code or read the whole file." Only
  Claude Code `Edit` and `MultiEdit` edits are counted. A file with an edit
  that overlaps either end of the window, or that Vibra cannot count, is left
  out. See [Code checks](../features.md) for the rule and its known limits.
- **A related OWASP category on each Review Agent Activity finding.** Credential
  reads, this project's `.env` named and guardrails off relate to ASI03. A
  denied call that ran later, a write outside the workspace and a force push
  relate to ASI02. Vendor credential rejections and vendor usage relate to
  none. `--incidents --json` carries an `owasp` array on every row. A vendor
  report draft adds one "Related OWASP category (Top 10 for Agentic
  Applications 2026)" line after the facts. It is context, not a finding
  against the vendor.
- **`--evidence-stats`** change lines carry `target=source`, `test.compared` or
  `test.unseen`, and new `qualified agent= effect=` lines count rows whose
  test-edit sentence names an effect.

## Changed

- **Release build.** `make app ARCHS="arm64 x86_64" HARDENED=1` builds a
  universal app with the hardened runtime and the Apple Events entitlement.
  `make dmg` only packages an existing bundle and never rebuilds.
  `tools/release/package.sh` is the one script both CI and the release
  workflow run. A plain `make app` is unchanged.

## What Vibra now stores

Nothing new. Test-edit text is read in memory to count pattern matches and
dropped. A test file's path becomes an in-memory hash key. Vibra still makes
no network request.

## Verification

- `make test SWIFT_BUILD_SYSTEM=native`: 563 tests in 61 suites passed on
  macOS 27 with Swift 6.4, including the four privacy canaries.
- CI run 43382966703 passed on the macOS 15 runners, Apple Silicon and Intel.
  On both, the app inside the mounted DMG reported `lipo -archs: x86_64
  arm64`, the hardened runtime and a matching CDHash, and kept running for
  20 s. On Apple Silicon a throwaway signing identity was imported into a
  temporary keychain and removed again.
- An independent Python oracle (`tools/evidence-oracle`) implements the same
  rule. On the owner's 30 days of sessions, its `--evidence-stats` counts
  matched the Swift build on every change, check and reported line, in both run
  orders. The only differences were sessions that started between the two
  runs. Neither found a qualifying row. So on that data the test-edit sentence
  appeared 0 times.
- The privacy canary failed, as intended, when the path key kept the raw path
  and when it was built from the edit text. It passed again once restored.
- The notarization status, `stapler validate`, both `spctl` checks and the
  `TeamIdentifier` check are filled in after task 14.

## Limits still open

- The test-edit sentence has the known limits listed in `docs/features.md`. On
  the owner's own 30-day data it fired 0 times.
- Whether the Apple Events entitlement is needed for Return to Session is
  decided by plan task 11, a live check on a Mac.
- There is no prebuilt Homebrew cask yet. The tap still builds from source.
