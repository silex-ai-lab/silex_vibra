# Fix log — Vibra held ~27% CPU while idle (2026-10-05)

The installed Vibra (running since 2026-09-27) sat at 26–27% CPU with no agent
doing anything, and had accumulated ~1783 CPU-minutes. Two causes: a
self-sustaining refresh loop (the bug), and per-refresh work that made each
loop iteration expensive (the amplifier). Both fixed; macOS 15 (Darwin 24.6).

## Diagnosis

1. `sample <pid> 5`: almost all non-idle time under
   `SessionStore.performRefresh()` → `SessionIngest.refresh()`, split between
   `ClaudeCodeAdapter.sources()` → `jsonlFiles(under:)` (directory
   enumeration, `getattrlistbulk`) and SQLite `jsonParseValue` (the Cursor
   adapter's `json_extract`).
2. `Vibra --bench`: one warm refresh ≈ 50 ms. Not slow by itself, so it was
   running far too often.
3. An FSEvents listener on exactly Vibra's watched directories (same flags,
   0.25 s latency) received **84 batches in 20 s**, every one of them for a
   single path: `Cursor/User/globalStorage/state.vscdb-shm`.
4. Cursor's main app was **not running**; `state.vscdb` and `-wal` were last
   modified the previous evening, `lsof` showed no holder — yet the `-shm`
   mtime advanced every ~0.5 s. The only reader was Vibra.

## The loop

```
refresh → CursorAdapter opens state.vscdb read-only and queries it
        → SQLite (WAL mode) writes the -shm wal-index, as every reader does
        → FSEvents on the globalStorage directory → requestRefresh()
        → describeDatabase() folds -shm mtime into the descriptor → "changed"
        → Cursor query re-runs (join + json_extract over 298 sessions, 19 MB)
        → -shm written again …
```

`-shm` is shared memory for the wal-index; readers write it, so its mtime
says nothing about new data. Real writes always land in the main file or
`-wal`.

## Fix 1 — break the loop

- `OpenCodeAdapter.describeDatabase` (shared by Cursor, Hermes, OpenCode) and
  `FileWatcher.pollSignature` fingerprint the main file and `-wal` only.
- `FileWatcher.handleEvents` drops `-shm` paths; a batch with nothing else
  left fires no refresh.
- `SessionStore` polls Cursor's `state.vscdb` (1 s, like OpenCode/Hermes)
  instead of FSEvents-watching the whole `globalStorage` directory, which also
  holds constantly-written cursor-agent-worker logs.
- Tests: `touchingSHMLeavesDescriptorUnchanged`, `pollIgnoresSHMButSeesWAL`,
  `shmOnlyEventsDoNotFire`.

Result on the installed app: CPU 27% → 0.4–0.9%; `-shm` mtime static over 5 s.

## Fix 2 — make each refresh cheap

- **Cursor horizon filter.** `SourceInput.databaseSnapshot(since:)` carries the
  ingest horizon; `CursorAdapter.update` binds it into the one allowlisted
  SELECT (`?1 IS NULL OR h.lastUpdatedAt >= ?1`). Real profile: 32 ms → ~0.
  `discoverSessions()` (History, Report) still reads everything. Trade-off: a
  long-idle session resumed mid-turn appears once Cursor updates its header —
  the first seconds of the turn (see `Row.isMidTurn`).
- **Directory scan cache.** `JSONLTreeScanner` caches each directory's listing
  keyed by its mtime (which moves only on add/remove/rename) and re-reads only
  directories that changed. Used by `ClaudeCodeAdapter.sources()` and
  `CodexAdapter.sources()`. `~/.claude/projects` (294 dirs): 28 ms → <1 ms.
- **Bare `lstat` in `SourceDescriptor.describing`.** `attributesOfItem` adds
  xattr and owner-name lookups: 7.7 ms vs 0.3 ms for 273 files.
  - Trap: building the `Date` from 1970 (`sec + nsec/1e9`) differed in the last
    bit from Foundation's `contentModificationDate` on 393 of 783 files, which
    broke the incremental-equals-full-parse test for VS Code. Built from the
    reference date with `1e-9 * nsec`, as Foundation does, it matched 783/783.
- Tests: `refreshLeavesSessionsOlderThanTheHorizonOutOfTheQuery`,
  `JSONLTreeScannerTests` (matches a full enumeration; sees nested add, new
  directory, delete; drops a removed directory).

## Verified 2026-10-05

- `make test`: 172 tests pass (7 new).
- `Vibra --bench` warm refresh: 33 ms → 2.5 ms (after Fix 1; ~50 ms before it),
  unchanged refresh still reads 0 bytes.
- `--dump-sessions` identical between the old and new builds.
- Installed with `make install SIGN_IDENTITY="vibra local signing"`; 60 s
  steady state used 0.2 s CPU.
